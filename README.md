1.   THE DANGERS OF DATA REDUNDANCY

When a company stores the same customer's address in three different tables,this will indeed cause a problem because the information that is stored for one customer is repeated in the database, so this is called data redundancy.For instance if a customer moves to a new house decides to update their address, the company must remember to change the address in all three tables. If they only change the address in one table then the database will habe different addresses for the same customer. This can cause confusion because the emplyees might use the wrong address to deliver packages or even when sending letters. It can lead to more mistakes and make the information in the database false or unreliable. And another problem the company might face is that the company wastes storage space by storing the same information in different tables and this takes more time and effort to update the information because the same changes must be made in different tables so the simple way to avoid this type of a problems is to store the customer's address in one main customer table and allow other tables to connect to the main one. This helps to store the correct information, organised and easy to manage. 


2.  PRIMARY VS FOREIGN KEY ENFORCEMENT

A Foreign Key helps to make sure that information in one table is connected to a record tha already exists in another table. It acts like a safety check because it prevents the database from having records that do not belong to anything. For example when a company has a Customer table and an Orders table. The Customers table stores customer information, while the Orders table stores the orders made by each customer. Every customer will have its own unique customer id, which is the Primary Key. The Orders table uses the customer id as a Foreign Key to show which customer placed the order. If someone tries to add an order using a customer id that does not exist in the customer table, the database will reject it. This prevents non-existing records, which are records that are not connected to any existing record. So the Foreign Keys help keep the database organised, correct and also realible.
